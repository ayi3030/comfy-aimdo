## 4. 失败回退方案

| 阶段 | 失败现象 | 回退/排查动作 |
|------|----------|---------------|
| 构建 | `aimdo_xpu.so` 编译失败 | 先确认 CUDA/HIP 目标仍可编（`-DAIMDO_CUDA` 路径未动）；XPU 目标失败不影响既有后端。 |
| 加载 | `control.init()` 返回 False | 检查 loader：`LD_DEBUG=libs` 确认 `libze_loader.so.1` 可加载；`dmesg`/驱动是否就绪。 |
| (a) | `zeVirtualMemReserve` 返回非 0 | 驱动未支持 VMM → 本机降级：不启用 aimdo（`lib=None`），ComfyUI 走默认 `torch.xpu` 分配器，功能不中断。 |
| (b) | PyTorch 不识别 VMM VA | ✅ **已实测 PASS，该风险消除**（`VERIFY_real_b580.md` §3）；原「最大不确定性」不再成立。 |
| 运行 | 显存不足/OOM | 调 `control.set_simple_vram_headroom()`；或禁用 aimdo。 |

**总回退**：本项目对 CUDA/HIP 完全向后兼容；XPU 侧若未验证通过，可仅保留 Track 1（Python 层）——插件在 Intel 环境干净禁用，不影响 ComfyUI 正常运行。

## 5. 风险与未决项

- **R1**：Level Zero VMM 在 B580 实际可用性 —— ✅ **已关闭**（(a) PASS）。
- **R2**：PyTorch 能否识别 VMM 设备 VA —— ✅ **已关闭**（(b) PASS；原「最大不确定性」不再成立）。
- **R3**：`ZE_STRUCTURE_TYPE_PHYSICAL_MEM_DESC` ~~数值（0x1D）~~ **已核实为 `0x20`**，`CONTEXT_DESC=0x0D` 经驱动接受（`实现说明.md` §2）；XPU 后端**已编译部署**（`VERIFY_real_b580.md` §4）。
- **R4**：`xpu_memcpy_htod_async` 为空实现 → hostbuf 文件→显存加载在 XPU 上暂不生效，需用 `zeCommandListAppendMemoryCopy` 补齐。
- **R5**：设备总显存 —— ✅ **已接入真实查询** `zeDeviceGetMemoryProperties`（真机实测 **11.60 GiB**）；`XPU_FALLBACK_VRAM`(12GiB) 仅作兜底。
- **R6**：`zeVirtualMemReserve`/映射的 size 对齐需按 `zeVirtualMemQueryPageSize` 结果；当前按查询到的页大小向上对齐，若实际页大小更大需复核。
